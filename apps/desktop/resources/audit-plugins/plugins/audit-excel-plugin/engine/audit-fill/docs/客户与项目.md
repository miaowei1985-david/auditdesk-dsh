# 客户与项目模型

## 一、结构

```
client（客户）
  └── project（项目：期间 + 业务类型）
        ├── project_file（资料：tb / fs / voucher）
        ├── 底稿（fills / checks，挂在 company.name 上）
        └── 阶段（stage：资料接收→…→归档）
```

- 一个客户可有多个项目（如 2025 年报审计、2026 年报审计、专项审计）；
- 项目代码规则：`<客户>-<期间>`，如 `中天-2025`；
- 资料按项目保存路径，换项目不串数据；
- 底稿输出：2025 项目沿用 `out/<客户>/底稿包`；其他期间输出到 `out/<客户>/<期间>/底稿包`，避免覆盖。

## 二、工具

| 工具 | 作用 |
|---|---|
| `audit_clients` | 列出客户与项目（阶段、资料数） |
| `audit_project_create` | 新建项目（客户不存在时自动建） |
| `audit_project_attach` | 给项目挂 tb/fs/voucher |
| `audit_project_run` | 按项目资料生成底稿，推进到「勾稽核对」 |
| `audit_workflow` | 看流程阶段与下一步 |
| `audit_review` | 复核签字（进入归档） |

## 三、典型用法

```
> 新建客户「某某公司」2026 年报审计项目
> 给它挂上科目余额表和报表
> 跑这个项目

> 现在有哪些客户、各自到哪一步了
> 某某公司-2026 复核，复核人张三
```

## 四、与旧接口的关系

旧工具（`audit_fill_process` / `audit_status` / `audit_memo`）按「公司」工作；
新模型把「公司」升级为「客户 + 项目」。两者共用同一份底稿数据：
`project` 通过客户代码关联 `company.name`，2025 项目与既有底稿一一对应。

## 六、和「客户与项目」页面的集成（2026-11-23）

工作台插件 `@local/dsh-audit-workbench` 的「审计底稿」分区新增按钮
**「本机引擎生成（全量勾稽）」**：

- 从网关 `/audit/pbc` 取项目资料清单，按文件名挑 tb/fs/voucher；
- 下载附件后 POST 到 `POST /api/audit-fill/run`（`@local/audit-excel` Host 插件注册的同源路由）；
- 本机引擎跑完返回逐项勾稽，页面回显「勾稽 x/y 一致；差异 …；输出目录」。

这样「客户与项目」里的项目，可以直接用本套 Excel 填表方法生成底稿，不再只是静态展示。

## 七、回传与附件选择（2026-11-23）

- 页面「审计底稿」工具栏：余额表/报表/凭证三个下拉框（默认自动匹配 PBC 附件）；
- 生成后自动回传网关：`POST /audit/workpapers/upload`（新增于 server.py，已部署、冒烟 PASS），
  右侧「已生成底稿」即可预览/下载；
- 全链路实测：临时项目 → 本机引擎 6 个文件全部回传 → 网关列表可见 → 删除临时项目。
